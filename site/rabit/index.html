rabit

A small JSON manifest that tells agents what your site or repo holds and where, so they can find things without crawling. People get a readable map too.

Get started Read the spec

A burrow at a glance

One file at the root of your site or repo lists what's there. Each entry has an id, a kind and a URI.

{
  "specVersion": "fwdslsh.dev/rabit/schemas/0.4.0/burrow",
  "kind": "burrow",
  "title": "My Documentation",
  "entries": [
    { "id": "start", "kind": "file", "uri": "start.md" },
    { "id": "api", "kind": "burrow", "uri": "api/" }
  ]
}

Core concepts

Burrows

A collection of content described by a .burrow.json manifest. A table of contents an agent can read before it starts crawling.

 Warrens

A registry of burrows, published as a .warren.json. One place to index several docs sites or repos.

 Navigation

Agents follow links in manifests instead of guessing URLs or scraping HTML.

 Any transport

Works over HTTP, Git or local files. The format is the JSON, not the transport.

Why rabit?

The web is built for human eyes. Agents struggle with complex layouts, client-side JavaScript and inconsistent navigation. A burrow gives them a plain map that sits beside your site.

HTML only

Visual, unstructured, crawled and guessed at.

vs

HTML + a burrow

Structured, JSON-first, read directly.
